================================================================================
REPORTS FOLDER - Automated Report Generation
================================================================================

PURPOSE:
This folder contains the automated report generation infrastructure. It reads
test results from the Testing/Data/ folder and generates comprehensive audit
reports in markdown format. Reports document validation status, pass/fail counts,
and module-specific findings.

================================================================================
FOLDER STRUCTURE
================================================================================

Reports/
├── run-reports.ps1                  PowerShell report generator (Windows)
├── run-reports.sh                   Bash report generator (Linux/Mac)
├── Instructions.txt                 This file
└── Data/
    ├── nodejs-report.md             Final report for nodejs module
    ├── php-report.md                Final report for php module
    ├── python-report.md             Final report for python module
    └── vscode-report.md             Final report for vscode module

Related: generate-reports.ps1 (root folder) - Wrapper script for convenience

================================================================================
HOW TO GENERATE REPORTS
================================================================================

IMPORTANT: Run tests first!
Tests must complete successfully before generating reports.
See Testing/Instructions.txt for test execution details.

WINDOWS (PowerShell):
---------------------
From the root folder (e:\Working\Learning\dev):

  powershell -ExecutionPolicy ByPass -File "Reports/run-reports.ps1"

Or use the wrapper script:

  powershell -ExecutionPolicy ByPass -File "generate-reports.ps1"

Or run directly from Reports folder:

  cd Reports
  powershell -ExecutionPolicy ByPass -File "run-reports.ps1"

LINUX/MAC (Bash):
-----------------
From the root folder:

  bash Reports/run-reports.sh

Or run directly:

  cd Reports
  bash run-reports.sh

EXPECTED OUTPUT:
- Reports generated for each module
- Files written to Reports/Data/*-report.md
- Console output showing generation status
- Report files displayable in VS Code or any markdown viewer

================================================================================
HOW TO MANUALLY GENERATE REPORTS (If Automation Fails)
================================================================================

STEP 1: Verify Test Results Exist
----------------------------------
Check that test results are available:

  Testing/Data/nodejs_module_results.md
  Testing/Data/php_module_results.md
  Testing/Data/python_module_results.md
  Testing/Data/vscode_module_results.md

If any are missing, run tests first (see Testing/Instructions.txt)

STEP 2: Create Report File Manually
------------------------------------
Create a markdown file in Reports/Data/ following this template:

```markdown
# {MODULE_NAME} Module - Comprehensive Audit Report

**Report Generated:** YYYY-MM-DD HH:MM:SS

## Executive Summary

- **Module:** {MODULE_NAME}
- **Total Tests Run:** X
- **Tests Passed:** Y
- **Tests Failed:** Z
- **Success Rate:** X%

## Test Coverage Analysis

### Category Name
- Description of what was tested
- Total tests in category: X
- Passed: Y
- Failed: Z

### {Category 2}
- Description
- Tests: X (Passed: Y, Failed: Z)

## Detailed Test Results

### Passing Tests (Y passed)

1. Test Name - Result description
2. Test Name - Result description

### Failing Tests (Z failed)

1. Test Name - Reason for failure
2. Test Name - Reason for failure

## Module Structure Status

- Backup scripts: [✓] Present and validated
- Restore scripts: [✓] Present and validated
- Configuration files: [✓] In place
- Data directory: [✓] Organized correctly

## Recommendations

1. Recommendation 1
2. Recommendation 2
3. Recommendation 3

## Files Analyzed

- /path/to/script1.ps1
- /path/to/script2.ps1
- /path/to/config.json

---
*Report prepared for module validation and integrity verification*
```

STEP 3: Use Existing Test Results
----------------------------------
If you want to manually format existing results:

1. Open Testing/Data/nodejs_module_results.md (example)
2. Copy the test results section
3. Create Reports/Data/nodejs-report.md
4. Add introduction and recommendations
5. Format consistently with other reports

================================================================================
UNDERSTANDING REPORT STRUCTURE
================================================================================

REPORT FILE: *-report.md

Each report contains:

1. HEADER SECTION
   - Module name
   - Generation timestamp
   - Overview metrics (tests run, passed, failed)

2. EXECUTIVE SUMMARY
   - Quick statistics
   - Success rate percentage
   - Overall module health

3. COVERAGE ANALYSIS
   - Tests grouped by category
   - Pass/fail counts per category
   - Coverage percentage per area

4. DETAILED RESULTS
   - List of all passing tests with checkmarks [✓]
   - List of failing tests with reasons [✗]
   - Failure descriptions for debugging

5. MODULE STATUS
   - Presence/validation of key files
   - Directory structure verification
   - Configuration status

6. RECOMMENDATIONS
   - Actions to fix failing tests
   - Best practices for module
   - Next steps for improvement

7. FILE MANIFEST
   - List of all files analyzed
   - Helps trace what was included in audit

================================================================================
READING AND INTERPRETING REPORTS
================================================================================

SUCCESS CRITERIA:

✓ Green (Passing): Tests pass validation
  - Scripts have correct syntax
  - Required files exist
  - Security patterns found
  - Structure is correct

✗ Red (Failing): Tests failed validation
  - Check the reason provided
  - Review the recommendation
  - See Testing/Instructions.txt for manual test steps

METRICS:

Success Rate = (Tests Passed / Total Tests) × 100

Expected:
- Below 80%: Module needs attention
- 80-95%: Module is mostly healthy
- 95%+: Module passes comprehensive validation

CATEGORIES:

Different test categories validate different aspects:
- Syntax: PowerShell/Bash/JSON validity
- Security: Error handling, input validation
- Structure: Required files and organization
- Documentation: Comments and descriptions
- Completeness: All expected scripts present

================================================================================
TROUBLESHOOTING REPORT GENERATION
================================================================================

PROBLEM: "Test results not found" error
SOLUTION:
  1. Run tests first: Testing/run-tests.ps1
  2. Wait for tests to complete
  3. Verify Testing/Data/ has result files
  4. Check file names match exactly

PROBLEM: Reports are empty or incomplete
SOLUTION:
  1. Check test results are not empty
  2. Verify Testing/Data/*_module_results.md have content
  3. Manually add missing sections
  4. Ensure .md files have valid markdown

PROBLEM: Report generation takes too long
SOLUTION:
  1. Normal: Generating 4 reports takes 5-10 seconds
  2. If longer: Check disk space
  3. Try running individual report generation from Reports folder
  4. Check no other processes accessing files

PROBLEM: Can't read generated reports
SOLUTION:
  1. Open in VS Code with markdown preview
  2. View raw markdown file (Reports/Data/*.md)
  3. Ensure file encoding is UTF-8
  4. Try online markdown viewer if local viewer fails

PROBLEM: Reports don't reflect latest tests
SOLUTION:
  1. Re-run tests: Testing/run-tests.ps1
  2. Verify old results are overwritten
  3. Then regenerate reports
  4. Check timestamps in report header

================================================================================
MANUAL REPORT WORKFLOW
================================================================================

If automated reports fail completely:

1. Create markdown file in Reports/Data/

2. Copy standard report template (shown above)

3. Extract data from Testing/Data/
   - Count passed/failed tests
   - List test names and results
   - Calculate success percentages

4. Write analysis section
   - Identify patterns in failures
   - Note categories with issues
   - Suggest fixes

5. Save with standard naming:
   Reports/Data/{module}-report.md

6. Verify formatting is consistent with other reports

================================================================================
INTEGRATION WITH AUTOMATION
================================================================================

FULL AUTOMATION FLOW:

1. Developer runs tests:
   Testing/run-tests.ps1
   → Creates Testing/Data/*_module_results.md

2. Developer generates reports:
   Reports/run-reports.ps1
   → Reads from Testing/Data/
   → Creates Reports/Data/*-report.md

3. Developer reviews reports:
   View Reports/Data/*-report.md in VS Code
   → Identifies issues
   → Fixes module scripts if needed

4. Optional: Run again:
   Testing/run-tests.ps1 (after fixes)
   → Reports/run-reports.ps1 (for updated report)

WRAPPER SCRIPT:

generate-reports.ps1 (at root) combines steps 2:
  powershell -ExecutionPolicy ByPass -File "generate-reports.ps1"
  → Calls Reports/run-reports.ps1

================================================================================
BEST PRACTICES
================================================================================

1. Always run tests before generating reports
2. Keep reports organized in Reports/Data/ only
3. Review reports after each module update
4. Commit reports to version control for history
5. Compare reports over time to track improvements
6. Use failure suggestions as code improvement checklist
7. Document any manual tests in corresponding result files
8. Share reports with team for transparency
9. Update tests when validation rules change
10. Archive old reports if keeping detailed history
